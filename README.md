# Aba Avner

Minimal cross-platform (macOS/Linux/Windows) GUI app to scan a directory (recursively), detect visually similar images, and copy only unique images into a new folder.

## Install
<a href="https://apps.microsoft.com/detail/9N1JBPN874G7"><img src="https://get.microsoft.com/images/en-us%20dark.svg" alt="Get it from Microsoft" height="56"></a>
<a href="https://snapcraft.io/aba-avner"><img src="https://snapcraft.io/static/images/badges/en/snap-store-black.svg" alt="Get it from the Snap Store" height="56"></a>

- Windows: `winget install 9N1JBPN874G7` or the Microsoft Store link above
- Linux: `sudo snap install aba-avner`

## Build from source
Needs the [requirements](#requirements) below, Rust, and `cargo install tauri-cli`.
```sh
git clone https://github.com/tomerdev1/aba-avner.git
cd aba-avner/src-tauri
cargo tauri build   # also builds the UI; bundles land in src-tauri/target/release/bundle/
```
All commands below run from the repo root.

## Tech Stack
- Tauri v2 + Rust backend
- Plain HTML/CSS/JS frontend
- Perceptual hashing (dHash)
- Rust unit/integration tests with `cargo test`
- UI tests with `vitest`
- Visual UI regression tests with Playwright screenshots

## Project Layout
- `src-tauri/` — Rust backend + Tauri config
- `ui/` — static frontend assets
- `auto-tests/` — image fixtures used by backend integration tests

## Tests
Backend tests cover:
- image scanning and extension filtering
- perceptual hashing and Hamming-distance behavior
- duplicate/near-duplicate grouping
- minimum image size filtering
- recursive scanning and copying unique images

UI tests cover:
- missing-Tauri fallback messaging
- localization persistence and live switching
- state transitions, controller behavior, and render output
- cancel flow handling, repeated run regression coverage, and settings persistence
- forwarding user-configured settings values to the backend

Visual UI tests cover screenshot regressions for:
- idle state
- progress state
- canceling state
- completed state
- warning flood state
- failure flood state

## Packaging
Review and build the desktop bundle:
```sh
cd src-tauri
cargo tauri build
```

`cargo tauri build` now prepares `ui/dist` during the Rust build via `src-tauri/build.rs`, so a clean checkout no longer needs a separate manual UI build just to satisfy Tauri's `frontendDist` check.

Or from the repo root:
```sh
make package
```

For release-ready verification, prefer the repo-root entry point:
```sh
make release-check
```

`release-check` auto-detects the local platform and runs the matching bundle verification. You can also override the platform explicitly:
```sh
./scripts/release-check.sh linux
./scripts/release-check.sh macos
./scripts/release-check.sh windows
```

Verify Linux bundle artifacts manually:
```sh
cd src-tauri
cargo tauri build --bundles appimage,deb,rpm
python3 scripts/verify_bundle_outputs.py linux
```

Packaging/configuration readiness in this repo currently includes:
- app metadata and bundle icon in `src-tauri/tauri.conf.json`
- explicit Tauri capability permissions in `src-tauri/capabilities/default.json`
- automatic `ui/dist` preparation during GUI Rust builds
- explicit standalone UI production build via `cd ui && npm run build`
- explicit bundle artifact verification via `src-tauri/scripts/verify_bundle_outputs.py`
- strict Snap packaging scaffolding in `snap/snapcraft.yaml`

Build a strict-confinement snap locally:
```sh
snapcraft pack --destructive-mode
```

The snap definition currently assumes the supported strict flow is:
- reading and writing regular user files via the `home` interface
- optional access to USB/external drives via `removable-media`

Because this is a strict snap, hidden dot-directories in `$HOME` and arbitrary
system paths are not part of the default supported publish target.

## Microsoft Store
See [`docs/microsoft-store-submission.md`](docs/microsoft-store-submission.md).
Recommended path: MSIX, built via `tauri-windows-bundle` and uploaded by CI as the
`windows-msix` artifact — free code signing (Microsoft re-signs it) and free
automatic updates via Windows Update. A plain NSIS installer (`cargo tauri build
--bundles nsis`, built locally or via `./scripts/release-check.sh windows` — CI
no longer builds this automatically) also works as a direct EXE/MSI submission,
but needs a paid code-signing certificate and the custom
`tauri-plugin-updater` self-update flow to get any updates at all.

## Verification Levels
Use these repo-root entry points instead of reconstructing the closeout command list by hand:

- `./scripts/test-all.sh` or `make smoke`: fast local smoke loop
- `./scripts/smoke-full.sh` or `make smoke-full`: capability review, dependency audits, backend tests without GUI features, the ignored `synthetic_dataset_full_hash_smoke`, backend tests with GUI features, UI tests, and visual regression tests
- `./scripts/release-check.sh` or `make release-check`: `smoke-full` plus `npm run build`, platform-specific `cargo tauri build --bundles ...`, and `python3 src-tauri/scripts/verify_bundle_outputs.py <platform>`

`smoke-full` exists so the real ignored dataset smoke test is easy to run from the repo root without remembering `--ignored --exact --nocapture`.

## Release Gates
Production-ready changes are expected to pass `make release-check` on the target platform before shipping.

CI enforces these gates in `.github/workflows/ci.yml` before the packaging matrix runs.
The packaging matrix installs UI dependencies with `npm ci`, and the Tauri/Rust build then prepares `ui/dist` as part of the GUI build itself.

Capability review is intentionally strict: `src-tauri/capabilities/default.json` must remain limited to:
- `core:default`
- `dialog:default`
- `updater:default`

If broader permissions are required later, update the review script and document the reason before shipping.

`cargo audit` is currently expected to pass with allowed warnings rather than a fully clean advisory set. The remaining warnings are mainly in the Linux GTK3 / WebKit dependency chain used by Tauri packaging, so treat that as ongoing supply-chain risk to review during release work.


```sh

```

- `ui/coverage/index.html`

The coverage run includes:
- Rust backend tests via `cargo llvm-cov`
- UI `vitest` tests via V8 coverage

The Playwright visual suite is not included in code coverage.

## Cleanup
Remove generated artifacts without touching source files:
```sh
make clean-generated
```

This cleanup target removes only generated directories:
- `coverage/`
- `ui/coverage/`
- `ui/dist/`
- `ui/test-results/`
- `src-tauri/target/`

Typical local reset loop:
```sh
make clean-generated
make build-ui
make test-ui
```

## Notes for Future AI Sessions
- Every big task must follow:
  - `AI_WORKFLOW.md`
- Tauri v2 requires explicit permissions. Dialog permissions are in:
  - `src-tauri/capabilities/default.json`
- Bundle output assertions live in:
  - `src-tauri/scripts/verify_bundle_outputs.py`
- UI uses `window.__TAURI__.core.invoke` (v2 API).
- Runtime UI copy is localized at render time; `ui/index.html` is intentionally string-light.
- If the dialog button is disabled, ensure the app was restarted after permission changes.
